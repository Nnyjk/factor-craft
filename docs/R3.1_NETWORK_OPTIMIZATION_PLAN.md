# R3.1: 网络包优化实现计划

## 目标
减少网络流量，优化同步频率，降低服务器负载

## 当前问题分析

### 1. Factor 浓度同步
**问题**: 当前 Factor 浓度同步频率过高，可能每 tick 都在同步
**影响**: 大量网络包导致服务器 TPS 下降

**解决方案**:
- 将同步频率从每 tick 改为每秒 (20 ticks)
- 仅当浓度变化超过阈值时才同步
- 使用懒加载：仅同步玩家附近区块

### 2. 机器状态同步
**问题**: `markDirty()` 每 tick 调用导致频繁同步
**影响**: 100+ 机器同时运行时网络包爆炸

**解决方案**:
- 添加状态变化检测：仅当状态真正变化时同步
- 添加同步冷却：同一机器最小同步间隔 500ms
- 批量同步：多个机器状态变化时合并发送

### 3. 网络包压缩
**问题**: 无压缩配置，大数据量传输占用带宽
**影响**: 多人服务器带宽占用高

**解决方案**:
- 添加配置选项启用/禁用压缩
- 对大数据包使用压缩算法
- 添加包大小阈值配置

## 实现步骤

### Step 1: 添加网络配置系统
**文件**: `NetworkConfig.java`
**内容**:
```java
public class NetworkConfig {
    // Factor 同步配置
    public static int FACTOR_SYNC_INTERVAL_TICKS = 20; // 1 秒
    public static double FACTOR_SYNC_THRESHOLD = 0.1; // 浓度变化阈值
    
    // 机器状态同步配置
    public static int MACHINE_SYNC_COOLDOWN_MS = 500; // 500ms 冷却
    public static boolean MACHINE_STATE_CHANGE_ONLY = true;
    
    // 压缩配置
    public static boolean ENABLE_COMPRESSION = true;
    public static int COMPRESSION_THRESHOLD_BYTES = 256;
}
```
